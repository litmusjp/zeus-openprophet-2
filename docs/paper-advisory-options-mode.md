# Paper advisory options mode

`PAPER_ADVISORY_OP2` is an explicit opt-in for using AlphaDesk's scanner-independent `paper_advisory_greeks_v1` assessment as a trade-quality gate on opening options orders in a verified PAPER account.

Configure `ALPHADESK_EXECUTION_MODE=PAPER_ADVISORY_OP2`, `ALPHADESK_ENABLED=true`, and `ALPHADESK_SIGNAL_QUALITY_ENABLED=true`. Managed connections also set `ALPHADESK_REQUIRE_MANAGED_APPROVAL_GATE=true` in the Go backend environment. Keep the OpenProphet account's paper setting and operator authorization enabled separately.

For a managed connection, AlphaDesk uses the versioned assessment-only contract. Its `approval_gate` contains a strict `required` boolean, positive `revision`, and `{workspace_id, assessment_key_id}` scope. A managed receipt does not include the legacy flat `execution_allowed` or `human_approval_required` flags. PASS means only that assessment criteria passed; it never grants broker authority. A locked gate returns `UNAVAILABLE`, a null score, and `human_approval_required` as its blocker. Unmanaged legacy connections retain their existing contract.

The agent may assess an exact proposal with `prophet_assess_options_trade`; FAIL or UNAVAILABLE skips the opening. `prophet_place_options_order` independently obtains and validates the exact proposal, durably audits it, then performs a fresh current-policy read near broker submission. Managed revision and scope must match the receipt and the gate must be OFF; a change to either toggle invalidates old clearance. Existing account permission, paper identity, risk, exposure, reservation, reconciliation, and managed-execution checks remain independently required. Unsupported proposals and any missing, invalid, stale, mismatched, or non-PASS receipt fail closed. Closing or reducing exposure continues through existing guarded close paths. A policy change can still race with a request already past its final check; this gate does not cancel dispatched or working orders.

This mode does not change `ACCOUNT_VERIFIED`, `SIGNAL_QUALITY_OP2`, or execution-grade `STANDALONE_OP2`. It does not enable execution for live accounts, change Greek provenance, or activate agents automatically. Preview acceptance and runtime activation are separate operational steps; local mock tests are not real-market acceptance.
